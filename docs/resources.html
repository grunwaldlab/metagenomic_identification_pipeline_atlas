Long range and context text is clipped to keep rows a consistent height; the complete values remain in the editable CSV files.

The score is a relative resource-efficiency index: RAM and database-disk maxima are ranked within this pipeline set with lower use scoring higher, and speed rank favors faster workflows. The three components are averaged on a 0–1 scale; unavailable RAM or database bounds receive a neutral midpoint. It is a planning aid, not a performance benchmark. Range columns retain their text summaries, sort by their largest numeric bound in GB, and use that bound for background shading. Approximate ranges are provided in resource_estimates.csv where literature measurements are absent; unavailable values remain uncolored. Speed sorts by meaning (Low < Low-Medium < Medium < High), not alphabetically.

Wall-clock time is not converted to CPU-hours unless core utilization is reported. Not reported means the reviewed sources did not support a defensible value.

By target taxon

The literature did not establish comparable per-sample RAM, CPU-hours, database bytes, and output bytes separately for viruses, bacteria, archaea, fungi, plants, animals, and protists. Available measurements are usually platform minima or untargeted bacterial/mock-community examples. Database contents, sample read count, host fraction, sequencing technology, and retained assembly intermediates can outweigh the organism group as resource drivers.

Target group Evidence available Main gap
Viruses VirMake recommends at least 64 GB RAM and 200 GB free disk; this is a platform recommendation. CZ ID’s reduced viral test setup documents 16 GB RAM and more than 10 GB disk. No comparable per-virus sample CPU-hours, peak RAM, or results storage.
Bacteria IDseq reports 3 hours mean elapsed time (1.6–10 hours) on benchmark data, without core count. SqueezeMeta reports a 42-million-paired-read example on a 16 GB VM. Not a matched benchmark; CPU-hours and output bytes are unavailable.
Archaea Covered by microbial profilers and broad-reference workflows. No archaeal-only resource profile.
Fungi Supported by selected classifiers and domain-specific references in some workflows. No fungi-only resource profile or common database footprint.
Plants Broad databases may return plant sequence hits; plant viruses are the focus of neighboring workflows such as Kodoja. No included plant-target community resource benchmark.
Animals Animal/host genomes are often used for host subtraction, not as target-community profiles. No animal-target community resource benchmark.
Protists Some broad or domain-specific databases can support protozoa/microbial-eukaryote calls. No protist-only resource profile.

The historical Kraken 2 standard database example is about 100 GB to build, including a 29 GB compact hash table; it dates to 2018 and is a tool-level illustration, not a current per-sample estimate (manual). SURPI’s historical comprehensive indexes total roughly 783 GB, but that is based on 2013 NCBI data and should not be used as a modern planning figure.
